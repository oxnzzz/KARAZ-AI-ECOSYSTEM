## 3. Commands

Run in a Linux x86-64 container (kernel 6.18), Git 2.43.0. `unshare -rn` gave each scan a network namespace containing only the loopback interface; a host lookup from inside it failed. The clone and the downloads happened before the scans, outside that namespace.

```text
git clone --mirror https://github.com/oxnzzz/karaz-ai-ecosystem mirror.git
git -C mirror.git archive 87eb795480c8768e1ffe8e8cb97dc5b042c30d2b | tar -x -C tree

unshare -rn gitleaks git mirror.git \
  --config <v8.30.1 config.toml> --redact=100 --report-format json --report-path <scratch>/git-N.json \
  --no-banner --ignore-gitleaks-allow --gitleaks-ignore-path <empty directory> --exit-code 0

unshare -rn gitleaks dir tree \
  --config <v8.30.1 config.toml> --redact=100 --report-format json --report-path <scratch>/dir-N.json \
  --no-banner --ignore-gitleaks-allow --gitleaks-ignore-path <empty directory> --exit-code 0
```

`gitleaks git` scans `git log -p -U0 --full-history --all --diff-filter=tuxdb` over the mirror. `--exit-code 0` only keeps the exit status at 0 so that the report is always written; the findings are read from the report. Report files were written outside the repository and are not committed.

## 6. Limitations

* **Binary provenance** is limited as stated in section 2: the missing embedded revision means source-to-binary provenance was not established.
* **One tool, default ruleset.** Gitleaks detects secrets by rule and entropy. It can miss secrets that match no rule, are low-entropy, are split or encoded, or are in binary files. A clean result is not proof that no secret exists.
* **No live credential validation.** No live credential validation was performed. Gitleaks 8.30.1 matched patterns only; it did not test whether any matched string was an active credential, so a clean result says nothing about whether a credential would work.
* **Scope is Git content.** Not scanned: issues, pull-request descriptions and comments, review comments, GitHub Actions logs and artifacts, wiki, releases, forks, and other repositories.
* **Refs.** Only the 13 refs in the baseline manifest (§1) were scanned: the refs that a mirror clone received on 2026-11-21. A mirror clone can contain pull-request merge refs for pull requests that are currently open (a mirror taken later contained `refs/pull/7/merge`), while the original mirror held no merge refs because every pull request open at that time had been closed, so the baseline has pull-request head refs only. Objects that are unreachable from the 13 refs, any server-side refs that a mirror clone does not receive, and anything deleted from GitHub before the clone were not scanned.
* **Point in time.** The result covers the subject commit and the history up to it. Later commits, including the one that adds this record, are not covered.
* **Run environment.** The scan was run by an AI assistant in an ephemeral cloud container. The only parties who can confirm it are the owner (by re-running it) and a human reviewer.
* **No GitHub security features.** GitHub Secret Scanning, push protection and Dependabot were not enabled or used, and no scan workflow exists.
* **Not behavioral evidence.** This record says nothing about how any skill behaves (`docs/EVIDENCE-MODEL.md` §4).
* **Not reviewed.** No human has compared this record with a re-run of the scan. Until then it does not support `repository_security_scan: "recorded"` in `registry/skills.yaml`, which remains `"not_run"`.
* **Reuse for a release.** Using this scan for a skill release requires that the skill's directory is unchanged between `87eb795480c8768e1ffe8e8cb97dc5b042c30d2b` and the release commit (`docs/EVIDENCE-MODEL.md` §9).
